## Сборка под Linux

Шаблон написан на C (C11). Нужны компилятор (gcc или clang), CMake не ниже
3.10 и GLFW 3.3+.
На Debian/Ubuntu:

```bash
sudo apt install build-essential cmake libglfw3-dev
```

Сборка (из корня шаблона):

```bash
cmake -S . -B build
cmake --build build -j
```

По умолчанию собирается **Release** (`-O3 -march=native`). Для отладки
соберите отдельную Debug-версию в другую папку:

```bash
cmake -S . -B build_debug -DCMAKE_BUILD_TYPE=Debug
cmake --build build_debug -j
```

Измерять скорость растеризатора имеет смысл только в Release-сборке.

## Сборка под Windows


Сборка CMake(из корня шаблона):

```bash
cmake --build build -j --config Release
```

## Запуск

Пути к ресурсам по умолчанию заданы относительно корня шаблона, поэтому
запускайте программы оттуда.

### main_cli

```bash
./build/main_cli [mesh.obj] [texture.png|jpg] [output.png]
```

Загружает меш (по умолчанию `resources/Bunny.obj`), печатает число вершин и
треугольников, затем загружает картинку (по умолчанию
`resources/textures/porcelain.jpg`) и сохраняет её с переставленными красным
и синим каналами (по умолчанию в `swapped_rb.png`).

### main_app

```bash
./build/main_app [width] [height]
```

Открывает окно (по умолчанию 640×480) и каждый кадр заполняет на CPU массив
RGBA8 цветом, который плавно меняется со временем; массив выводится в окно
через `glDrawPixels`. Скорость смены цвета умножается на длительность кадра,
поэтому не зависит от FPS. Раз в секунду в консоль печатается среднее время
кадра. Выход - `Esc` или закрытие окна.

Вертикальная синхронизация выключена (`glfwSwapInterval(0)`), чтобы время
кадра показывало реальную скорость программы, а не частоту монитора.

## Соглашения

### Векторы (`vectors.h`)

В шаблоне есть только типы `vec2`, `vec3` и функции `make2`, `make3` - то,
что нужно загрузчику мешей. Операции над векторами, `vec4`, матрицы и прочую
математику дописывайте сами (в этот же файл или в свой).

### Картинки (`image_utils.h`)

* Картинка - массив `float` размером `w * h * channels`, каналы пикселя лежат
  подряд (RGBRGB...).
* **Строки хранятся снизу вверх**: пиксель `(x, y)` лежит по адресу
  `data[(y * w + x) * channels]`, `y = 0` - нижняя строка картинки.
  Так же устроены буфер `glDrawPixels` в `main_app` и текстурная координата
  `v` в `.obj`. Если вы выберете другое соглашение, поменяйте его везде.
* `load_image_f32_rgb(filename, &w, &h, gamma)` загружает RGB-картинку
  (3 канала), переводит значения в [0, 1] и возводит в степень `gamma`
  (`gamma = 1` - без преобразования). Возвращает массив, который нужно
  освободить через `free()`, или `NULL` при ошибке.
* `save_image_f32_png_rgb(data, filename, w, h, channels, gamma)` возводит
  значения в степень `1/gamma`, обрезает в [0, 255] и пишет PNG. Принимает
  1 (только красный канал), 2 (R, G) или 3 и больше (RGB, остальные каналы
  игнорируются) каналов, поэтому в PNG можно сохранить и кадровый буфер, и,
  например, буфер глубины.

### Меши (`mesh_utils.h`)

* Все атрибуты вершины индексируются одним индексом: `verts[i]`,
  `normals[i]`, `tcs[i]`. Треугольник `t` - вершины `indices[3*t]`,
  `indices[3*t+1]`, `indices[3*t+2]`.
* В `.obj` у позиций, нормалей и текстурных координат индексы раздельные.
  При загрузке каждая уникальная тройка (позиция, текстурная координата,
  нормаль) становится отдельной вершиной, поэтому вершин в меше может
  оказаться больше, чем строк `v` в файле (например, на швах развёртки).
* Многоугольники разбиваются на треугольники.
* Нормали и текстурные координаты **не генерируются**: если в файле их нет
  (или они заданы не для всех вершин), `normals` / `tcs` равны `NULL`.
* При ошибке `load_obj` возвращает пустой меш (`num_triangles == 0`).
  Освобождается меш через `free_mesh`.
* Файлы материалов (`.mtl`) не используются.

## Соглашения

| Вопрос | Выбор |
|---|---|
| Векторы | столбцы: `p' = M * p`, конвейер `p_clip = P * V * M * p` |
| Хранение матриц | `m[строка][столбец]` (row-major) |
| Порядок в матрице модели | `M = T * R * S` (применяется справа налево: масштаб, поворот, перенос) |
| Система координат | правая |
| Камера (видовое пр-во) | в начале координат, смотрит вдоль −z, вверх +y |
| Глубина в NDC | [−1, 1]: near → −1, far → +1 (как в OpenGL) |
| Экран | x вправо, y вверх; строка 0 кадрового буфера — нижняя (при сохранении в PNG строки переворачиваются) |
| Пиксель (i, j) | квадрат [i, i+1) × [j, j+1), центр в (i + 0.5, j + 0.5) |
| Углы | в радианах |
| Точки / направления | w = 1 / w = 0 (`point()` / `dir()`) |

Viewport: `xs = (x_ndc + 1) / 2 * W`, `ys = (y_ndc + 1) / 2 * H`.

Отсечение: треугольник отбрасывается целиком, если у любой вершины
`w_clip < near` (near = 0.01). Края экрана не отсекаются: bounding box
треугольника обрезается по кадру.

## Структура

```
src/math/vectors.h      vec2/3/4, dot, cross, normalize, point/dir
src/math/mat.h/.c       mat3/mat4: умножение, транспонирование, обращение
                        (Гаусс-Жордан с выбором главного элемента),
                        translate/scale/rotate, look_at, perspective
src/render/framebuffer  кадровый буфер float RGB
src/render/raster       растеризация треугольника: bounding box + функции ребра,
                        барицентрическая интерполяция
src/render/context      контекст рендера: камера (V, P, VP раз за кадр),
                        вершинный этап, деление на w, viewport
src/test_math.c         модульные тесты математики
src/main_cli.c          рендер модели в PNG
```
